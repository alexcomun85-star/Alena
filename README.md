## Афита: переработка подбора и мобильного интерфейса, 29.10.2026

Причины: исходный подбор искал подстроку только в шести карточках сайта; фраза голосом без запятых не разбиралась. Несколько рядов кнопок и повторный заголовок отнимали мобильный экран. Подбор занятий открывал системные select.

Новый `js/recipe-engine.js` — локальный распознаватель русских названий продуктов и форм слов, 37 шаблонов приготовления, раздельные результаты с полным составом и с недостающими продуктами. У запроса без продуктов есть быстрые наборы. Неизвестные названия явно показаны, произвольные блюда не выдумываются. Поддерживаются исключения из состава. Это ограниченная, проверяемая библиотека, не универсальная генерация рецептов; количества и калорийность блюд не рассчитываются. Базовый подбор не вызывает модель и не отправляет продукты в сеть.

Интерфейс: одна компактная строка инструментов, при переключении возвращается начало экрана, сохраняются текущие поля сессии, результаты выдаются после явной кнопки. Формат выбирается радиокнопками. Результаты и рецепты можно сохранить в итог без дублей, удалить отдельно и выгрузить PDF. Для неизвестного продукта есть ручной расчёт по этикетке, каталог марок загружается один раз за сессию. Голосовой ввод зависит от сервиса браузера. Личные черновики не сохраняются в localStorage. Окно и основной чат остаются отдельными iframe, авторизация сервера сохранена.

Прототип нового сценария подготовлен в MagicPath (проект 466654561000640512, компонент 466654609834938368). Исходные снимки с телефона использованы для разбора и сравнения. Логика защищена `tests/recipe_engine.test.cjs`; браузерный набор `tests/assistant_actions.py` проверяет конкретную жалобу, недостающие продукты, пустой набор, варианты занятий без select, итог, PDF и переключение вкладок. ## Автоматические открытые источники в Афите, 30.10.2026

`js/online-data.js` подключает существующий сервер AlenaFit API. Если нет полного локального рецепта либо остались неизвестные продукты, после кнопки подбора выполняется поиск по русскоязычным рецептам Викиучебника. Если в локальной базе нет продукта, после паузы ввода запускается существующий поиск perek.us, с резервом Open Food Facts на сервере. Расчёты выполняются только с полными корректными БЖУ. Сервер имеет ограниченные фиксированные upstream-адреса, тайм-ауты и кэш запросов. На клиенте есть кэш, задержка ввода продуктов, отмена устаревших запросов и проверка доменов ссылок. При отключении внешнего источника локальные функции сохраняются. Произвольный поиск по всем сайтам интернета не реализован: используются только подключённые публичные базы.

## Упрощённая Афита и подбор по КБЖУ, 30.10.2026

Текущая версия заменяет ограничения первой версии недельного меню. Стартовый экран — шесть карточек задач без полей. Для недели два пути: автоматическая оценка по возрасту, росту, массе, полу формулы и активности либо ручная цель калорийности. Необязательные исключения, своя цель белка, доля жиров, силовые тренировки и режим безжировой массы находятся в дополнительных настройках. Поля переключаемого пути выключаются, скрытые обязательные поля не мешают отправке. Черновик действует в сессии; последний вес журнала подставляется только по явной кнопке.

`js/nutrition-targets.js`: Миффлин — Сан Жеор для расхода в покое (возраст 19–78 лет — область исходной выборки), приближённый множитель активности 1,4/1,6/1,8 по выбранному образу жизни. Дефицит 10% / прибавка 5% — явно обозначенные начальные настройки сервиса, не универсальные клинические предписания. Ручная цель не изменяется повторно. 1500 ккал больше не нижний порог. Для обычного автоматического меню поддерживаются значения больше 1200 и до 5000 ккал; 1200 и ниже направляются к индивидуальной оценке, а не объявляются безопасными по росту. При низком ИМТ снижение веса автоматически не предлагается.

Белок для физически активного режима: рабочие 1,6 г/кг внутри диапазона ISSN 1,4–2,0. Для обычного меню — рабочий шаблон 20% энергии, не ниже популяционного ориентира EFSA 0,83 г/кг. Это не равнозначно индивидуальной физиологической потребности. При ИМТ от 30 используется доля энергии с пояснением, что белковую цель следует проверить индивидуально. Режим БЖМ только при авторасчёте, выбранном дефиците и подтверждённых силовых: известный процент жира, БЖМ = масса × (1 − % жира / 100), рабочие 2,3 г/кг БЖМ — нижняя граница специализированного диапазона ISSN 2,3–3,1. Процент жира не угадывается. Своя цель белка имеет приоритет. Жиры по умолчанию 30% энергии (настройка 20–35% по EFSA), углеводы — остаток; выход за популяционный ориентир EFSA 45–60% явно отмечается. Проверка энергии по 4/9/4 допускает округление и отличия пищевых баз, в частности из-за клетчатки. Источники доступны в интерфейсе и PDF.

`fitDay` подбирает граммовки ограниченным координатным спуском по четырём целям, мягко учитывая распределение по приёмам пищи и размер исходных порций. Это численная оптимизация меню, не медицинская формула. Технические допуски: ±5% энергии, ±15% каждого БЖУ; недостигнутые цели показываются явно. Ограничения продуктов сохраняются. После замены пересчитывается весь день; в сохранении теперь есть фактические порции, поэтому восстановление не меняет оптимизированный план. Старые сохранения по ID поддерживаются. Все функции расчёта работают локально без запросов к модели.

Макет коротких сценариев обновлён через MagicPath в прежнем проекте 466654561000640512, компонент 466654609834938368, ревизия 466846117116649472. Макет демонстрирует интерфейс и не выдаёт фиктивные медицинские расчёты. Рабочая реализация остаётся в существующем статическом сайте.
