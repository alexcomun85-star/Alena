# ALENAFIT: SEO-аудит и безопасная оптимизация

Дата: 31.10.2026. База: `d769a70bde449d90538369b7b0998c32ee296ebe`.
Объект: https://alenafit.com/, https://github.com/alexcomun85-star/Alena.
Изменения подготовлены к согласованию; публикация и слияние запрещены без решения владельца.

## 1. Общая оценка

Техническая основа хорошая: статические HTML, 20 содержательных и 3 служебные страницы, локальные шрифты, относительные ссылки. Все 20 содержательных страниц имеют уникальные title/description, один H1, абсолютный canonical на HTTPS без www. В исходном HTML нет пропусков уровней H1–H6. Все img имеют alt, width и height; качество каждого описания требует визуальной проверки. Главное изображение — JPG около 132 КБ с fetchpriority=high, ниже первого экрана применяется lazy loading; сами по себе JPG не являются ошибкой. Изображения занимают около 2,6 МБ на весь репозиторий, а не на одну загрузку.

Не найдено подтверждённых критических препятствий обходу основных URL. Индексация, позиции, поисковый трафик и реальные Core Web Vitals НЕ установлены. Техническая доступность и Sitemap не подтверждают присутствие в индексе.

## 2. Проблемы и доказательства

| Приоритет | Наблюдение | Доказательство и значение | Решение |
|---|---|---|---|
| Важное | Offline запрещён к обходу, хотя содержит noindex | robots.txt: Disallow /offline.html; offline.html: meta robots noindex. Запрет мешает роботу увидеть noindex | Убрана только эта директива Disallow; noindex сохранён |
| Важное | Название главной не содержит фамилии, калькулятор слабо обозначен как калькулятор | inventory-before.json; «Алёна…», «Еда: калории и БЖУ без диет» | Уточнены title/description без изменения предложения услуг |
| Важное | Разборы науки: в title 8, в description 9 | nauka.html, исходные метаданные в inventory-before.json | Метаданные без хрупкого числа публикаций |
| Важное | Содержимое рецептов и новостных лент зависит от JS | js/recepty.js создаёт 6 карточек через innerHTML; js/feeds.js загружает data/*.json | Следующий этап: статический HTML при сборке с сохранением JS. В текущую ветку не включено из-за риска изменения рецептов и интерфейса |
| Важное | Нет полученных данных поискового спроса и индексации | Нет доступного коннектора Search Console/Вебмастера; Wordstat не вернул статистику выбранных запросов | Выгрузки владельца; семантика пока гипотеза без частотности |
| Дополнительное | Генератор Sitemap проверял noindex буквальной подстрокой | scripts/build_sitemap.py: зависимость от кавычек, регистра и порядка атрибутов | HTMLParser; проверки robots/googlebot/yandex, noindex/none |
| Дополнительное | Нет WebSite | Главная содержала только Person | Добавлен WebSite с существующим Person как publisher; без SearchAction, рейтингов и неподтверждённых Offer |
| Дополнительное | /index.html отвечает 200 и дублирует / | http-before.json; одинаковые SHA256; canonical уже указывает / | Не менять адреса; canonical сохранён. Серверный 301 рассмотреть только при смене конфигурации хостинга |

HTTP GET: все 23 HTML и robots.txt/sitemap.xml — 200; заведомо отсутствующий URL — 404. Прямой запрос /404.html возвращает 200 с noindex: сам по себе это не soft 404 для отсутствующих адресов. HTTP и www доходят до HTTPS без www. Цепочки записаны в redirects.json. Проверка выполнена из одной среды через её сетевой прокси; это не проверка из сетей Googlebot или Яндекса.

Локальные href/src существуют. Якоря в статическом HTML найдены; шесть якорей рецептов создаются js/recepty.js — их существование после выполнения JS в этом сеансе не проверено. Первичная инвентаризация пропускала ссылки без path, затем отдельная SEO-проверка проверила и их. Поэтому отсутствие битых статических ссылок не выдаётся за полный браузерный обход.

Опубликованные 23 HTML и дополнительный /index.html совпали по SHA256 с базовым коммитом. Публичный Sitemap уже генерируется при деплое и имеет актуальные даты; старые даты в версионируемом файле не означают старую публичную карту.

## 3. Приоритеты и семантическое ядро

Полная карта всех 20 страниц: SEMANTICS.csv. Для каждой указан основной запрос, намерение и роль страницы. Частотность нигде не придумана. Поиск подтвердил наличие коммерческих предложений конкурентов по теме персональных онлайн-тренировок в Петербурге, но число предложений не доказывает частоту запросов. До Wordstat/GSC не называть ядро проверенным спросом.

Главная — основная коммерческая страница тренера/нутрициолога, очных мини-групп и онлайн-сопровождения. trener.html — информационное сравнение самостоятельных занятий и сопровождения, а не второй дубль коммерческой главной. pitanie.html — образовательная страница, а не посадочная медицинской консультации. kalorii.html — расчёт состава еды, не обещание медицинской нормы. vozvrat.html — план возвращения после паузы. Запрос «женский фитнес СПб» широкий: без проверки выдачи нельзя считать его приоритетнее точного запроса мини-групп.

Порядок: получить измерения → согласовать текущий PR → при подтверждённом спросе отдельно проектировать страницы онлайн-сопровождения и очных занятий. Пока не создавать конкурирующие посадочные и не размножать географические страницы.

Контент: в изученных разделах питания и сопровождения есть ссылки на исследования, ограничения и направление к врачу; квалификация представлена на главной. Полная медицинская экспертиза каждого утверждения и проверка каждого DOI не проводились. Нужны автор/проверяющий и реальная дата пересмотра важных материалов; дату не обновлять формально при каждой сборке. Не называть Алёну врачом-диетологом. Подтверждения квалификации из HANDOFF не заменяют согласования публичных сведений владельцем.

## 4. Выполненные изменения

- index.html: имя и география в метаданных, WebSite, согласованные социальные метаданные.
- kalorii.html, pitanie.html, nauka.html: более точные title/description и соответствующие социальные метаданные.
- golod.html, servisy.html, vozvrat.html: уточнены title и существующий og:title.
- robots.txt: робот может прочитать noindex offline-страницы.
- scripts/build_sitemap.py: разбор метатегов вместо буквальной подстроки.
- sitemap.xml: пересобран; тот же набор 20 канонических URL. Даты берутся из git; на деплое файл собирается снова с полной историей.
- tests/seo_check.py: повторяемая SEO-проверка; .github/workflows/pages.yml запускает её в PR и перед публикацией.
- docs/seo/: отчёт, семантика и исходные доказательства.

BreadcrumbList не добавлен: полноценная видимая иерархия крошек не внедрялась, а менять дизайн запрещено. Recipe не добавлен к персональным динамическим результатам. LocalBusiness не добавлен: адрес студии не подтверждает принадлежность или постоянное представительство Алёны. Person сохранён без вымышленных регалий.

## 5. Проверки

- SEO: 23 HTML, 20 индексируемых по настройкам. Уникальность метаданных, один H1, canonical, файлы ссылок, якоря (с отдельным учётом генерируемых рецептов), атрибуты img, синтаксис JSON-LD, состав XML Sitemap, варианты noindex — PASS.
- Сравнение body каждого из 23 HTML с базовым коммитом — идентичны. CSS, JS, сервер Афиты, данные, формы и офферы не изменены.
- Все 11 файлов tests/*.test.cjs через Node test runner — PASS. Включены питание, порции, рецепты, контракт ИИ, незавершённая генерация, хранение, PDF и меню.
- node server/meal-plan/test.mjs — PASS: квоты, восстановление, поэтапная генерация и балансировка на тестовых данных; без платных вызовов ИИ.
- git diff --check — PASS.
- JSON-LD: проверен синтаксис и базовые поля, НЕ полная валидация всех свойств Schema.org и НЕ Rich Results Test.

## 6. Непроверенное

Chromium не установлен: загрузчик Playwright получил некорректный архив. Поэтому браузерные Python-наборы, визуальная адаптивность телефона/планшета/ПК, фактические клики, PDF на физическом устройстве, работа Афиты с внешним сервером, Lighthouse и измерения LCP/INP/CLS не выполнены. PR запускает существующий браузерный CI; результат CI нужно посмотреть до слияния.

Полевые CWV нужно получить из PageSpeed Insights/CrUX и Search Console: ориентиры хороших значений — LCP ≤2,5 с, INP ≤200 мс, CLS ≤0,1 на 75-м процентиле. Локальный замер не заменяет полевые данные. Недостаток данных CrUX не означает прохождение CWV.

Полный Nu HTML Checker, Google Rich Results Test, Schema Markup Validator, реальные журналы роботов, индексирование Google/Яндекса, selected canonical и robots в инструментах поисковых систем не проверены. Статическая проверка не равна валидатору HTML.

Использованы GitHub, веб-поиск по официальным источникам, git, Python и Node. Product Design/Figma/Canva не требовались: интерфейс и графика не менялись. Context7 не требовался: новых библиотек frontend нет. PostHog в коде не обнаружен, данные его проекта не получены; трекер не подключался.

## 8. Требуется от владельца

1. Согласовать PR, проверить CI. До согласования main и действующий сайт не меняются.
2. Предоставить выгрузки GSC (эффективность за 3 месяца, индексирование, CWV, URL Inspection ключевых страниц) и Вебмастера (запросы, страницы в поиске, диагностика). Для подтверждения домена DNS TXT надёжнее размещения кода в открытом репозитории; значение берётся из кабинета.
3. Wordstat: СПб отдельно от РФ, точные формулировки/операторы, период и дата, выгрузить исходные числа; не суммировать вложенные широкие запросы.
4. Подтвердить актуальные контакты, расписание, цены, право указывать студию как место приёма, публичный телефон и часы связи. Телефон и постоянный адрес не выдумывать.
5. Яндекс Бизнес: очная карточка только для подтверждённого места обслуживания; иначе онлайн-компания с территорией услуг. В профиле и на сайте единые имя, Telegram, сайт, услуги; отзывы только реальные с согласия, без вознаграждения за положительную оценку.
6. Google Business Profile: Россия присутствует в официальном списке поддерживаемых стран. Возможность создания/подтверждения конкретной карточки проверяется в кабинете. Чисто онлайн-услуга без очного контакта не основание для карточки; для независимого специалиста в чужой студии сначала проверить критерии. Не создавать фиктивное представительство. Сайт не должен заявлять неподтверждённую принадлежность студии.
